개요

총에 맞으면 체력이 줄어드는 대신 몸이 날아가고, 마지막으로 상대를 밀어 떨어뜨린 사람이 킬을 가져간다. 발밑을 쏘면 로켓 점프를 할 수 있고, 상대 발밑을 쏘면 더 높이 띄울 수 있으며, 상자를 쏴서 상대를 밀어낼 수도 있다.

주요 기능

  • 게임 모드 5종: 개인전, 팀전, 크라운, 서바이벌, 펑 축구
  • 아레나 6종 + 펑 축구 전용 경기장: 기울어지는 바닥의 용광로, 눈보라 치는 얼어붙은 호수, 움직이는 열차가 있는 궤도 정거장 등
  • 스팀 온라인 멀티플레이 (방 만들기 / 방 코드로 참가), 로비
  • 난이도를 고를 수 있는 봇으로 혼자 연습, 빈자리 채우기
  • 튜토리얼 훈련장, 아이템, 연속 킬, 연장전, 경기 후 칭호와 하이라이트 리플레이
  • 스킨 커스터마이징, 스팀 도전과제 50개, 32개 언어 지원

역할

기획, 설계 결정, 테스트, 밸런싱, 출시 작업 등

AI 활용 방식

아이디어를 제외하곤 모두 AI를 사용하여 제작하였습니다. 대신 AI가 틀리지 않고, 내 의도대로, 확인된 결과만 내놓도록 일하는 방식을 설계하는 데 집중했습니다.

역할 나누기

  • 사람: 무엇을 만들지, 제대로 되었는지, 재밌는지를 결정
  • AI (Claude Code): C++ 구현, 기획 문서 갱신, 에디터 에셋 작업, 3D 메시 생성 스크립트, 31개 언어 번역, 성능 측정

규칙 문서로 AI 다루기 (CLAUDE.md)

  • 프로젝트 규칙을 문서로 정리해 모든 세션이 같은 기준으로 일하게 함: 코드 구조 원칙 (넉백, 킬 판정, 점수는 서버 권한, 무기 수치는 데이터 에셋에만), 손대지 말 것 (무기 수치 데이터), 커밋은 내가 말할 때만 하고 푸시는 금지
  • AI가 빠졌던 함정을 규칙으로 쌓아 같은 실수를 막음. 예: 언리얼 유니티 빌드에서의 이름 충돌, Git LFS 병합 충돌로 깨진 에셋, 저장된 것처럼 보이지만 디스크에 안 남는 나이아가라 에셋

환각 막기

  • 엔진 API와 콘솔 변수는 기억으로 쓰지 말고 엔진 소스에서 확인
  • 에셋, 맵 값은 짐작하지 말고 Unreal MCP로 읽어서 확인
  • "됐다"는 빌드 결과, 파일 수정 시각, 로그 같은 증거가 있을 때만 보고하고, 직접 못 본 것 (플레이 느낌 등) 은 "확인 안 됨"으로 따로 적게 함
  • 숫자는 직접 재거나 센 값만 쓰게 함

기획 문서를 단일 기준으로

  • GDD (기획 문서) 를 살아있는 문서로 두고, 기능을 바꾸면 같은 커밋에서 문서도 갱신
  • 결정을 하나하나 기록 (약 600건, 내가 직접 내린 결정은 따로 표시) → 세션이 바뀌어도 맥락이 이어짐

도구 연결

  • Unreal MCP: 에셋, 맵, 위젯, 나이아가라 이펙트를 AI가 에디터에서 직접 다루고 결과를 다시 읽어 확인
  • Blender MCP: 3D 메시를 파이썬 스크립트로 만들고, 스크립트를 원본으로 관리 (메시를 손으로 고치지 않음)
  • ElevenLabs: 효과음 생성. 프롬프트를 문서로 남겨 같은 소리를 다시 만들 수 있게
  • 전용 스킬 /arena-review: 맵의 이음매, 틈, 뒷면이 빈 메시 등을 정해진 기준으로 찾아 보고하는 검토 절차를 만들어 재사용

검증 체계

  • 자동 대전: 봇끼리 매치를 반복시켜 CSV로 기록하고 밸런스 데이터를 모음. 실행기 GUI로 봇 수, 모드, 맵, 속도를 골라 여러 대전을 동시에 돌림
  • 시험용 콘솔 명령: 길찾기 점검, 기믹 시험 등 특정 상황을 바로 재현하는 명령을 만들어 AI와 내가 같은 방식으로 확인
  • 성능 측정: 패키징 빌드에서 CSV 프로파일링과 Unreal Insights 트레이스로 측정
  • 손맛처럼 AI가 판단할 수 없는 것은 사람이 직접 테스트

AI 로그: 밸런스 조정

출발점은 GTA 온라인의 무기 "업앤아토마이저(Up-n-Atomizer)"입니다. 상대를 쓰러뜨리는 대신 날려 보내는 이 총을 기획 문서 첫 줄부터 레퍼런스로 적어 두었습니다. 2026.08에 웹 프로토타입으로 "밀어서 떨어뜨리는 게임"이라는 방향과 로켓 점프를 먼저 확인했고, 2026.10에 수치는 버리고 로직만 가져와 언리얼로 옮겼습니다.

AI에게 맡긴 것직접 한 것
봇끼리 자동 대전 실행과 기록밸런스 기준(킬 수, 게임 진행 시간) 정하기
기록 정리와 조정값 후보조정할 값(넉백, 위력, 연사, 장전 수) 정하기
정한 수치를 코드와 기획 문서에 반영최종 수치 결정, 직접 플레이로 손맛 확인

1. 상황 정의 구조화

  • 체력 없이 넉백만 있는 게임이라, 넉백 수치가 곧 "얼마나 쉽게 죽는가"를 결정
  • 초기 봇 대전 기록 (10.06 ~ 10.08): 사망까지 3.6~4.1발, 한 방 킬 56%, 사망의 20%가 스폰 직후, 연속 3발에 39m를 날아감

2. 문제, 목표 정의 구조화

  • 문제: 너무 쉽게 죽고, 태어나자마자 죽고, 연속으로 맞으면 너무 멀리 날아감
  • 목표: 밸런스 기준을 킬 수와 게임 진행 시간으로 정함
  • 원칙: 수치는 감이 아니라 봇 대전 기록으로 고치고, 손맛은 직접 테스트로 보완한다고 기획 문서에 명시

3. 작게 쪼개기 구조화

  • 조정할 값을 넉백, 위력, 연사, 장전 수의 네 가지로 나눔
  • 문제마다 고칠 곳을 하나씩 지정: 쉽게 죽음 → 상대 넉백 배율, 스폰 직후 사망 → 스폰 위치 규칙, 연속 피격 → 누적 넉백 상한

4. AI 협업 세팅 AI 리더십

  • AI가 만든 환경: 봇끼리 매치를 반복하는 자동 대전 모드, 여러 대전을 한꺼번에 띄우는 실행기, 넉백, 추락, 아이템, 매치 결과를 남기는 CSV 4종
  • 사람이 쥔 것: 기준과 최종 수치. 무기 수치 데이터는 AI가 임의로 바꾸지 못하게 규칙 문서에 명시
  • 검증: 수치를 바꾼 뒤 다시 대전을 돌려 기록으로 확인. 상대 넉백 배율을 0.82 → 0.7로 내린 뒤 사망까지 5.3발, 평균 생존 약 20초가 된 것을 확인

5. 실행하며 익히기 학습 실행력

  • 10.06: 중력 2배와 넉백 1500 → 2120 cm/s로 체공 시간만 단축. 발사 간격 0.25초 → 0.12초로 3발 연사 구현
  • 10.06 ~ 10.08: 스폰 위치를 무작위에서 "다른 플레이어에게서 가장 먼 지점"으로 변경. 연속으로 맞아 쌓이는 수평 속도를 한 발의 1.6배로 제한
  • 10.11: 맞히기는 쉽게, 한 방은 약하게. 근접 신관 130 → 170cm, 상대 넉백 배율 0.7 → 0.6
  • 10.17 (팀 합의): 로켓 점프가 너무 세서 기본 넉백 2120 → 2000 cm/s, 폭발 반경 300 → 350cm, 상대 넉백 배율 0.6 → 0.75로 조정
  • 킬 피드: 83매치, 844킬 기록에서 "공중" 태그가 54%에 붙을 만큼 흔해 기준을 조정. 5연속 킬이 10번 나온 것을 근거로 분노 오라 기준을 5연속으로 결정
  • 배운 것: 봇 기록은 수치를 다듬는 데까지만 유효. 사람끼리의 흐름과 전략은 봇으로 알 수 없어 손맛은 끝까지 직접 플레이로 확인

AI 로그: 레벨 디자인

맵은 모두 AI로 만들었습니다. 컨셉과 조건을 말로 전하고, 결과를 보고 고칠 곳을 짚고, 갈아엎을지를 정하는 일을 맡았습니다. 제가 맡은 맵은 붉은 절벽, 난파 해역, 용암 제련소의 1, 2안이고, 나머지 맵은 팀원이 같은 방식으로 만들었습니다.

AI에게 맡긴 것직접 한 것
맵 구조 설계와 크기 계산테마와 조건 제시
Blender 스크립트로 메시 제작, 언리얼에 배치결과를 보고 어색한 곳 짚기
기믹 구현 (C++ 액터)기믹 아이디어 제안, 여러 안 중 선택
정해진 기준으로 맵 검토, 봇 대전 점검사람끼리 플레이 테스트, 갈아엎을지 결정

1. 상황 정의 구조화

  • 링아웃 게임이라 맵이 곧 승패 규칙. 떨어질 공간, 대칭 구조, 리스폰 구역, 아이템 지점, 숨을 곳이 모두 필요

2. 문제, 목표 정의 구조화

  • 맵 크기를 한 방에 날아가는 거리에 맞춰야 함. 기준은 "가운데에서는 한 방에 나가지 않고, 가장자리 3~5m 안에서는 한 방에 나가는 정도"

3. 작게 쪼개기 구조화

  • 컨셉과 조건 → 메시 제작 → 배치 → 기믹 → 검토 → 플레이 테스트로 나누고, 단계마다 확인할 것을 정함

4. AI 협업 세팅 AI 리더십

  • 맡긴 방식: 좌표 없이 말로 컨셉과 조건만 전달. AI가 Blender 파이썬 스크립트로 메시를 만들고 Unreal MCP로 배치. 메시는 손으로 고치지 않고 스크립트를 고쳐 다시 생성
  • 검증: 검토 스킬 /arena-review로 이음매 틈과 한 면만 있는 메시를 측정 기준으로 검사하고, 봇 대전으로 점검. 용암 제련소는 뗏목 탑승이 10판 중 1번에서 8번으로 늘고, 봇이 갈 수 없던 구역이 275곳에서 34곳으로 감소
  • 직접 판단: 붉은 절벽은 구조가 진부해 3안으로 다시 만들고 4대4에 맞춰 0.85배로 축소. 쌍둥이 타워는 난간이 링아웃을 막아 폐기

5. 실행하며 익히기 학습 실행력

  • 실패를 규칙으로: 메시 40개가 저장되지 않아 헬기와 광장 없이 실행된 뒤 "가져오자마자 저장하고 파일 시각 확인"을, 회전값을 빼고 배치해 다리 39개가 돌아간 뒤 "항상 전체 위치값 전달"을 규칙 문서에 추가
  • 결과: 아레나 6종과 축구 전용 경기장, 훈련장, 대기방 완성. 출시 전 맵 9곳의 길찾기를 점검
