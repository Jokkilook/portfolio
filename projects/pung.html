개요

총에 맞으면 체력이 줄어드는 대신 몸이 날아가고, 마지막으로 상대를 밀어 떨어뜨린 사람이 킬을 가져간다. 발밑을 쏘면 로켓 점프를 할 수 있고, 상대 발밑을 쏘면 더 높이 띄울 수 있으며, 상자를 쏴서 상대를 밀어낼 수도 있다.

주요 기능

  • 게임 모드 5종: 개인전, 팀전, 크라운, 서바이벌, 펑 축구
  • 아레나 6종 + 펑 축구 전용 경기장: 기울어지는 바닥의 용광로, 눈보라 치는 얼어붙은 호수, 움직이는 열차가 있는 궤도 정거장 등
  • 스팀 온라인 멀티플레이 (방 만들기 / 방 코드로 참가), 로비
  • 난이도를 고를 수 있는 봇으로 혼자 연습, 빈자리 채우기
  • 튜토리얼 훈련장, 아이템, 연속 킬, 연장전, 경기 후 칭호와 하이라이트 리플레이
  • 스킨 커스터마이징, 스팀 도전과제 50개, 32개 언어 지원

역할

기획, 설계 결정, 테스트, 밸런싱, 출시 작업 등

AI 활용 방식

아이디어를 제외하곤 모두 AI를 사용하여 제작하였습니다. 대신 AI가 틀리지 않고, 내 의도대로, 확인된 결과만 내놓도록 일하는 방식을 설계하는 데 집중했습니다.

역할 나누기

  • 사람: 무엇을 만들지, 제대로 되었는지, 재밌는지를 결정
  • AI (Claude Code): C++ 구현, 기획 문서 갱신, 에디터 에셋 작업, 3D 메시 생성 스크립트, 31개 언어 번역, 성능 측정

규칙 문서로 AI 다루기 (CLAUDE.md)

  • 프로젝트 규칙을 문서로 정리해 모든 세션이 같은 기준으로 일하게 함: 코드 구조 원칙 (넉백, 킬 판정, 점수는 서버 권한, 무기 수치는 데이터 에셋에만), 손대지 말 것 (무기 수치 데이터), 커밋은 내가 말할 때만 하고 푸시는 금지
  • AI가 빠졌던 함정을 규칙으로 쌓아 같은 실수를 막음. 예: 언리얼 유니티 빌드에서의 이름 충돌, Git LFS 병합 충돌로 깨진 에셋, 저장된 것처럼 보이지만 디스크에 안 남는 나이아가라 에셋

환각 막기

  • 엔진 API와 콘솔 변수는 기억으로 쓰지 말고 엔진 소스에서 확인
  • 에셋, 맵 값은 짐작하지 말고 Unreal MCP로 읽어서 확인
  • "됐다"는 빌드 결과, 파일 수정 시각, 로그 같은 증거가 있을 때만 보고하고, 직접 못 본 것 (플레이 느낌 등) 은 "확인 안 됨"으로 따로 적게 함
  • 숫자는 직접 재거나 센 값만 쓰게 함

기획 문서를 단일 기준으로

  • GDD (기획 문서) 를 살아있는 문서로 두고, 기능을 바꾸면 같은 커밋에서 문서도 갱신
  • 결정을 하나하나 기록 (약 600건, 내가 직접 내린 결정은 따로 표시) → 세션이 바뀌어도 맥락이 이어짐

도구 연결

  • Unreal MCP: 에셋, 맵, 위젯, 나이아가라 이펙트를 AI가 에디터에서 직접 다루고 결과를 다시 읽어 확인
  • Blender MCP: 3D 메시를 파이썬 스크립트로 만들고, 스크립트를 원본으로 관리 (메시를 손으로 고치지 않음)
  • ElevenLabs: 효과음 생성. 프롬프트를 문서로 남겨 같은 소리를 다시 만들 수 있게
  • 전용 스킬 /arena-review: 맵의 이음매, 틈, 뒷면이 빈 메시 등을 정해진 기준으로 찾아 보고하는 검토 절차를 만들어 재사용

검증 체계

  • 자동 대전: 봇끼리 매치를 반복시켜 CSV로 기록하고 밸런스 데이터를 모음. 실행기 GUI로 봇 수, 모드, 맵, 속도를 골라 여러 대전을 동시에 돌림
  • 시험용 콘솔 명령: 길찾기 점검, 기믹 시험 등 특정 상황을 바로 재현하는 명령을 만들어 AI와 내가 같은 방식으로 확인
  • 성능 측정: 패키징 빌드에서 CSV 프로파일링과 Unreal Insights 트레이스로 측정
  • 손맛처럼 AI가 판단할 수 없는 것은 사람이 직접 테스트

AI 로그: 밸런스 조정

1인칭 멀티플레이 링아웃 슈터 / 출발점: GTA 온라인의 무기 "업앤아토마이저(Up-n-Atomizer)"입니다. 상대를 쓰러뜨리는 대신 날려 보내는 이 총을 기획 문서 첫 줄부터 레퍼런스로 적어 두었습니다. 2026.08에 미니게임 메이커스 챌린지용 웹 프로토타입으로 먼저 만들어 "밀어서 떨어뜨리는 게임"이라는 방향과 발밑을 쏘는 로켓 점프를 확인했고, 2026.10에 수치는 버리고 로직만 가져와 언리얼로 옮겼습니다.

아래는 밸런스 조정 한 가지를 AI와 어떻게 진행했는지에 대한 기록입니다.

AI에게 맡긴 것직접 한 것
봇끼리 자동 대전 실행과 기록밸런스 기준(킬 수, 게임 진행 시간) 정하기
기록 정리와 조정값 후보조정할 값(넉백, 위력, 연사, 장전 수) 정하기
정한 수치를 코드와 기획 문서에 반영최종 수치 결정, 직접 플레이로 손맛 확인

1단계: 문제

  • 수치를 감으로만 고치지 않도록, 봇끼리 매치를 반복시켜 데이터를 모으기로 결정
  • 사람의 손맛은 직접 테스트로 보완한다는 원칙을 기획 문서에 명시

2단계: AI에게 맡긴 것

  • 자동 대전 모드: 봇끼리 매치를 계속 돌리고 사람은 관전만 함. 봇 구성, 매치 수, 매치 시간, 배속, 모드를 실행 옵션으로 선택
  • 실행기: 위 옵션과 맵, 동시에 띄울 개수를 창에서 골라 여러 대전을 한꺼번에 실행
  • 기록: 넉백, 추락, 아이템, 매치 결과를 CSV 4종으로 저장

3단계: 데이터에서 나온 것

  • 너무 쉽게 죽음 (10.08): 벽을 걷어 낸 아레나에서 사망까지 3.6~4.1발, 한 방 킬이 56%
  • 태어나자마자 죽음 (10.08): 사망의 20%가 스폰 직후
  • 연속으로 맞으면 너무 멀리 감 (10.06): 연속 3발에 39m를 날아감
  • 킬 피드 태그가 흔함: 83매치, 844킬 기록에서 "공중" 태그가 54%, "연속" 태그가 28%에 붙음

4단계: 직접 정한 것

  • 상대 넉백 배율 0.82 → 0.7: 사망까지 5.3발, 평균 생존 약 20초로 개선
  • 스폰 위치: 무작위에서 "다른 플레이어에게서 가장 먼 지점"으로 변경
  • 누적 넉백 제한: 연속으로 맞아 쌓이는 수평 속도를 한 발의 1.6배로 제한. 한 발에 약 14m 날아가는 감각은 유지
  • 체공 시간과 연사 (10.06): 중력 2배와 넉백 1500 → 2120 cm/s로 체공 시간만 단축. 발사 간격 0.25초 → 0.12초로 3발 연사 구현
  • 맞히기 쉽게, 한 방은 약하게 (10.11): 근접 신관 130 → 170cm, 상대 대상 폭발 반경 배율 1.6 → 1.85, 상대 넉백 배율 0.7 → 0.6
  • 로켓 점프가 너무 셈 (10.17, 팀 합의): 기본 넉백 2120 → 2000 cm/s, 폭발 반경 300 → 350cm, 상대 넉백 배율 0.6 → 0.75. 몸이나 머리에 맞아도 뜨도록 최소 발사각 30° 추가
  • 킬 피드: 흔한 태그를 줄이고, 5연속 킬이 83매치에서 10번 나온 것을 근거로 분노 오라의 기준을 5연속으로 결정

5단계: 결과와 확인

  • 무기: 기본 넉백 2000 cm/s, 상대 넉백 배율 0.75, 폭발 반경 350cm, 충전 3발 (한 발 충전 1.5초), 발사 간격 0.12초
  • 매치: 제한 시간 5분, 킬 인정 시간 5초, 팀전 목표는 팀원 수 × 5킬, 동점이면 넉백이 1.25배가 되는 30초 연장전
  • 확인: 봇 기록으로 다듬되, 사람끼리의 흐름과 전략은 봇으로 다 알 수 없어 손맛은 직접 플레이로 확인

AI 로그: 레벨 디자인

맵은 모두 AI로 만들었습니다. 컨셉과 조건을 말로 전하고, 결과를 보고 고칠 곳을 짚고, 갈아엎을지를 정하는 일을 맡았습니다. 제가 맡은 맵은 붉은 절벽, 난파 해역, 용암 제련소의 1, 2안이고, 나머지 맵은 팀원이 같은 방식으로 만들었습니다.

AI에게 맡긴 것직접 한 것
맵 구조 설계와 크기 계산테마와 조건 제시 (떨어질 공간, 대칭, 스폰, 아이템, 숨을 곳)
Blender 스크립트로 메시 제작, 언리얼에 배치결과를 보고 어색한 곳 짚기
기믹 구현 (C++ 액터)기믹 아이디어 제안, 여러 안 중 선택
정해진 기준으로 맵 검토, 봇 대전 점검사람끼리 플레이 테스트, 갈아엎을지 결정

1단계: 문제

  • 링아웃 게임이라 떨어질 공간, 대칭 구조, 리스폰 구역, 아이템 지점, 숨을 곳이 모두 필요
  • 맵 크기를 한 방에 날아가는 거리에 맞춰야 함. 기준은 "가운데에서는 한 방에 나가지 않고, 가장자리 3~5m 안에서는 한 방에 나가는 정도"

2단계: AI에게 맡긴 것

  • 지시: 좌표 없이 말로 컨셉과 조건만 전달. 용암 제련소와 난파 해역은 컨셉까지 AI에게 맡김
  • 형태: AI가 Blender 파이썬 스크립트로 메시를 만들고 배치 좌표 파일과 함께 내보냄. 스크립트를 원본으로 삼아, 메시를 손으로 고치지 않고 스크립트를 고쳐 다시 생성. 맵 스크립트는 33개이고 긴 것은 2,000줄 이상
  • 배치: Unreal MCP로 맵 생성, 메시 가져오기, 배치, 머티리얼 정리까지 진행
  • 기믹: 맵에 놓기만 하면 동작하는 C++ 액터 29종으로 구현 (점프 패드, 무너지는 발판, 순환 보트, 열차, 기울어지는 바닥, 눈보라 등)

3단계: 검토와 검증

  • 검토 스킬 /arena-review: 이음매 틈, 한 면만 있는 메시, 밋밋한 바닥, 어긋난 에셋을 측정할 수 있는 기준으로 검사. 50cm 격자로 바닥을 훑어 틈을 찾고, 스폰 지점 눈높이에서 촬영해 확인
  • 검토 결과: 용암 제련소 6건, 난파 해역 5건, 대기방 7건의 문제 발견. 통로의 40~60cm 틈은 전용 메시를 새로 만들어 메우고, 돛대가 0.5m 앞을 가리던 스폰은 2.5m 이동
  • 봇 점검: 자동 대전을 맵마다 10판씩 실행. 용암 제련소의 뗏목 탑승이 10판 중 1번에서 8번으로 늘었고, 봇이 갈 수 없던 구역은 275곳에서 34곳으로 감소

4단계: 직접 개입한 것

  • 갈아엎기: 붉은 절벽은 2안의 구조가 진부해 3안으로 다시 제작. 쌍둥이 타워는 난간이 링아웃을 막아 폐기. 용암 제련소는 판 흐름을 바꾸는 기믹이 없어 기울어지는 주조장으로 교체
  • 아이디어: 난파 해역의 순환 보트는 "섬과 배 주변을 도는 보트를 발판으로 쓰자"는 제안에서 출발
  • 크기: 4대4에 너무 크다고 판단해 붉은 절벽을 0.85배로 축소
  • 세부 피드백: 끊긴 레일, 겹쳐서 깜빡이는 면, 너무 반듯한 절벽, 혼자 실사 같은 구름을 짚어 수정하고, 로우폴리 스타일 규칙으로 정리

5단계: 결과와 확인

  • 결과: 아레나 6종과 축구 전용 경기장, 훈련장, 대기방 완성
  • 규칙으로 남긴 것: 메시 40개를 저장하지 않아 헬기와 광장 없이 실행된 뒤로는 "가져오자마자 저장하고 파일 시각 확인", 회전값을 빼고 배치해 기지와 다리 39개가 돌아간 뒤로는 "항상 전체 위치값 전달"을 규칙 문서에 추가
  • 확인: 출시 전 맵 9곳의 길찾기를 점검하고, 패키징 빌드에서 맵별 성능을 측정
