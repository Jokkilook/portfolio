## 핵심 고민

- **상황**: 5일짜리 게임잼에서 지하 6층 레벨, 시설 에셋, 적 제작을 맡았습니다.
- **가장 고민한 것**: 결과를 하나하나 직접 고칠 시간이 없을 때, AI가 만든 결과의 품질을 어떻게 끌어올릴 것인가.
- **내린 답**: 제작 에이전트 하나와 기준이 서로 다른 리뷰 에이전트 셋을 묶어 "문제 0"이 될 때까지 고치게 했습니다. 방향 선택과 재미 판단은 직접 했습니다.

## 게임 소개

지하 6층 연구 시설에서 깨어난 주인공이, 약할 때는 드론의 시야를 피해 숨고 힘이 차면 각성해 시설을 부수며 한 층씩 올라가는 3인칭 액션 게임

## 프로젝트 정보

- 팀 구성: 3인
- 게임잼: 에픽 메가잼 (2026 Epic AI MegaJam), 주제 "디렉터스 컷(감독판)"
- 개발 기간: 2026.11.12 ~ 2026.11.16 (5일)
- 담당: 레벨 디자인, 에셋 제작, 적(드론, 터렛) 제작 (AI 및 에셋)
- 출시: [itch.io](https://jokkilook.itch.io/ignite) (Windows)
- 개발 방식: Claude Code + Unreal MCP, 역할별 서브에이전트
- 사용 기술: Unreal Engine 5.8, C++, Blueprint

## 개요

잼 주제 "디렉터스 컷"을, 힘을 잘려 나간 주인공이 봉인을 부수며 잘린 능력을 되찾고, 각성할 때마다 맵에서 무엇을 부수고 남길지 플레이어가 직접 "편집"하는 구조로 풀었다.

숨어 있으면 안전하지만 계속 약하다. 드론 시야의 가장자리를 스칠수록 힘이 차오르고, 가득 차면 점화해 벽과 기계를 부수며 나아간다. 각성이 끝나면 다시 어둠이지만, 내가 부순 것은 그대로 남아 지름길이 되기도 하고 드론에게 훤히 보이는 빈틈이 되기도 한다. 봉인 장치를 부수면 구속구가 하나씩 풀리며 능력이 돌아온다.

## 역할

### 레벨 디자인

- 격리층부터 연구층, 드론 격납고, 동력층, 보안 검문층, 통제 사령부까지 지하 6층 구성
- 층마다 다른 올라가는 방법 (계단, 리프트, 각성 점프로 오르는 수직 공간), 적과 엄폐물 배치
- 게임 시작 장면: 격리실에서 깨어나는 오프닝 시네마틱
- **만든 방식 (AI 사용)**: 평면도는 아래의 에이전트 루프로 설계하고, 6개 층 맵은 AI가 쓴 파이썬 스크립트로 생성. 플레이어 크기, 격납고 연출 같은 방향은 직접 결정

### 에셋 제작

- 시설 내부와 봉인 장치 등 레벨 에셋
- 파괴 연출: 드론, 터렛 폭발, 콘크리트 덩어리, 철판 파편
- 효과음
- **만든 방식 (AI 사용)**: 시설 내부, 소품, 봉인 장치, 파편은 AI가 Blender 파이썬 스크립트로 제작하고 에이전트 루프로 다듬음. 봉인 장치는 콘셉트 3안 중 하나를 직접 선택. 효과음은 ElevenLabs로 생성하고, AI는 소리를 들을 수 없어 직접 듣고 선택

### 적 (드론, 터렛): AI와 에셋

- 드론과 4족 터렛의 행동: 시야 원뿔로 감지, 추격과 수색, 잠든 기체로 돌아가기, 드론 사격(3연사), 터렛 연쇄 폭발
- 드론, 터렛 에셋과 애니메이션
- 최적화: 화면에 보일 때만 애니메이션 계산, 거리별 LOD (터렛 정점 약 65,000 → 최저 약 6,500)
- **만든 방식 (AI 사용)**: 드론과 터렛 모델은 Tripo(이미지 → 3D)로 초안을 뽑고, AI가 Blender MCP로 비율, 부품, 재질, 리깅을 다시 제작. 디자인은 여러 안 중 직접 선택했고, 첫 드론은 마음에 들지 않아 통째로 다시 제작. 행동 코드(C++)는 개발 에이전트가 작성

## AI 활용 방식

- 팀원마다 자기 파트(기획 / 월드 / 플레이어 / 보스)를 맡아 각자 Claude Code 세션으로 작업하고, 브랜치를 합쳐 완성
- 기획서(GDD), 팀 공통 인터페이스 문서, 작업 규칙(`CLAUDE.md`)을 먼저 만들고, 기획, 개발, QA, 아트 역할별 서브에이전트를 정의해 작업을 나눔
- 제작 에이전트가 만들고 리뷰 에이전트가 검토해 피드백을 주는 루프를 돌려, 결과물을 스스로 개선하게 함 (아래 "에이전트 루프")
- 자동 테스트(에디터 70여 개, 게임 월드 30여 개)와 맵 점검으로 변경을 확인하고, 손맛, 난이도처럼 AI가 판단할 수 없는 것은 사람이 플레이해서 결정
- 실수한 것을 LESSONS 문서에 기록해 다음 세션이 반복하지 않게 함 (예: 빌드하지 않은 변경을 커밋해 빌드가 깨진 건, 같은 작업 폴더를 쓰는 세션끼리 git 인덱스가 섞인 건)

### AI 로그: 에이전트 루프

제가 맡은 레벨과 에셋을 에이전트 루프(제작 → 리뷰 → 피드백 → 재작업)로 만든 기록입니다.

| AI에게 맡긴 것 | 직접 한 것 |
|---|---|
| 평면도 설계와 재설계 | 루프 구조와 리뷰 기준 세 가지 정하기 |
| 기준별 리뷰와 문제 목록 작성 | 라운드 상한과 멈출 시점 정하기 |
| 에셋 제작과 수정 (Blender 스크립트) | 스타일, 봉인 장치 콘셉트, 드론과 터렛 디자인 고르기 |
| 맵 생성, 에셋 적용, 기계 점검 | 효과음 듣고 고르기 |
| 적 행동 코드와 자동 테스트 | 직접 플레이해서 재미와 난이도 판단 |

#### 1. 상황 정의 {구조화}

- 5일짜리 게임잼에서 지하 6층 평면도, 시설 에셋, 적 제작을 담당

#### 2. 문제, 목표 정의 {구조화}

- **문제**: 짧은 기간에 만들 양이 많아, 결과를 하나하나 직접 고칠 수 없음
- **목표**: 완료 기준을 "리뷰 에이전트 셋 모두 문제 0"으로 정하고, 거기에 닿을 때까지 AI가 스스로 고치게 함

#### 3. 작게 쪼개기 {구조화}

- **작업**: 평면도 → 에셋(공용 키트, 소품, 파괴 오브젝트, 봉인 장치) → 맵 적용 순으로 나누고 묶음마다 루프 실행
- **리뷰 기준**: 한 에이전트가 한 가지만 보도록 분리. 레벨은 시설 개연성 / 진행 경로 / 층 이동 이야기, 에셋은 스타일 / 일관성 / 어울림

#### 4. AI 협업 세팅 {AI 리더십}

- **구성**: 제작 에이전트 하나와 리뷰 에이전트 셋
- **리뷰 방식**: 리뷰 에이전트는 라운드마다 새로 띄워, 이전 라운드와 다른 리뷰를 보지 않고 처음 보는 눈으로 평가. 문제마다 좌표나 수치 근거를 붙여 "문제"와 "제안"으로 나눠 작성
- **흐름**: 총괄 세션이 "문제"만 모아 수정 목록으로 만들어 제작 에이전트에게 전달
- **사람이 쥔 것**: 스타일과 디자인 선택, 라운드 상한, 재미와 난이도 판단. 리뷰 통과는 문서와 렌더 기준일 뿐이라 플레이 확인은 직접 진행

#### 5. 실행하며 익히기 {학습 실행력}

- **레벨 평면도**: 라운드별 문제 수 15 → 9 → 6 → 5 → 7 → 1 → 1 → 3 → 4 → 2 → 1 → 0 (12라운드)
- **수렴하지 않던 문제**: 6라운드를 넘기자 앞 라운드에서 덧붙인 설명이 새 문제를 만듦. "덧붙이지 말고 줄인다"로 방침이 바뀐 뒤에야 수렴
- **상한 조정**: 처음 6라운드였던 상한을 30으로 올리고, 마음에 들지 않은 라운드는 리뷰 없이 폐기
- **에셋과 맵 적용**: 공용 키트는 문제 14 → 6 → 2 → 0, 6개 층 적용은 7 → 3 → 3 → 5 → 0으로 통과
- **드론 재제작**: 첫 드론 모델은 여섯 번 고친 뒤에도 마음에 들지 않아 통째로 다시 제작하도록 지시
- **결과**: 지하 6층 맵, 공용 키트와 소품, 파괴 오브젝트, 봉인 장치, 드론과 4족 터렛을 게임에 적용
