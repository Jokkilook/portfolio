## 게임 소개

3D 멀티 생존 서바이벌 게임 (졸업 프로젝트)

## 프로젝트 정보

- 팀 구성: 5인
- 개발 기간: 2025.07 ~ 2026.06
- 담당: 플레이어 시스템, 인벤토리·제작, 저장 시스템, 멀티플레이 로비·접속, UI
- 사용 기술: Unreal Engine 5.5, C++, Blueprint, Steam (Advanced Sessions)

## 개요

외딴 섬에 조난된 플레이어들이 섬의 비밀을 파헤치고 탈출하기 위해 다양한 아이템을 수집하며 위협으로부터 생존하는 서바이벌 게임. 섬의 위협인 늑대 인간으로부터 생존해야 하며, 아이템을 모아 탈출선을 제작해 탈출해야 한다.

## 역할

### 플레이어 시스템 (C++, 멀티플레이)

- 걷기, 달리기, 웅크리기, 슬라이딩, 8방향 이동, 감정표현
- 수영: 부력 컴포넌트로 물에 들어갔는지 감지하고 수면/수중 모드를 나눠 산소 감소·회복 처리
- 공격: 애니메이션 노티파이 구간 동안 공격 지점을 스윕 트레이스로 이어서 판정. 애니메이션이 빨라도 판정에 빈틈이 생기지 않게 했고, 에임 방향 스피어 트레이스를 더해 조준한 곳에 정확히 맞도록 보정
- 핫바와 손에 든 아이템, 무기별 공격 모션을 데이터 테이블에서 불러오는 웨폰 컴포넌트
- 기절과 다른 플레이어의 부활, 사망·리스폰 (싱글 플레이는 사망 시 아침 시점으로 되돌림)
- 처음엔 클라이언트에서 직접 처리하던 동작을 "서버에 요청 → 서버에서 실행 → 결과 리플리케이트" 구조로 전면 리팩토링

### 상호작용 시스템

- 인터페이스 기반 액터 간 상호작용, 라인 트레이스로 대상 감지
- "꾹 눌러 상호작용" (아이템마다 필요 시간 설정), 크로스헤어와 진행도 표시
- 상호작용 요청을 서버에서 처리하도록 바꿔, 대상마다 따로 RPC를 만들지 않아도 서버 데이터를 다룰 수 있게 개선

### 스테이터스 컴포넌트

- 체력, 스태미나, 배고픔, 수분, 산소, 감염을 관리하는 컴포넌트. 수치 계산은 서버에서만 하고 클라이언트는 리플리케이트된 값을 표시
- 인벤토리 무게에 따라 스테이터스 감소량 증가, 피격 후 자동 회복

### 인벤토리 · 제작 · 상자

- 아이템을 UObject에서 구조체로 바꿔 인벤토리 리플리케이션 구현
- 드래그 앤 드롭, 우클릭으로 스택 나누기, 버리면 월드에 아이템 생성, 상자와 인벤토리 간 이동
- 데이터 테이블 레시피 기반 제작 (제작·요리·건축), 제작 시간 진행 바
- 통발, 수리 오브젝트 등 상호작용 오브젝트 제작

### 저장 시스템

- 저장 인터페이스와 직렬화(Serialize)로 액터 상태를 통째로 저장하는 범용 구조. 저장 가능한 액터는 컴포넌트까지 자동 저장·불러오기
- 월드에 떨어진 아이템, 베어낸 나무(폴리지) 상태, 플레이어별 데이터를 ID로 구분해 저장
- 자동 저장, 아침 저장, 세이브 슬롯 UI

### 멀티플레이 로비 & 접속

- 로비 시스템을 C++로 옮기고 리팩토링 (Advanced Sessions·친구 기능만 블루프린트 유지)
- 세션 코드로 방 입장, 역할 선택(중복 방지), 게임 도중 난입한 플레이어 처리, 강퇴
- 게임 스테이트 기반 채팅 시스템

### UI

- HUD, 인벤토리, 제작, 수리, 상자, 세이브 슬롯, 설정, 로비, 로딩 화면 등 게임 내 UI 디자인 및 개발

## 문제 해결

### 크래시 · 메모리

#### 삭제된 객체를 참조해 게임이 튕기던 문제 (타이머 · 델리게이트)

- 증상: 레벨을 다시 시작하거나 플레이어가 리스폰될 때 널 포인터 오류로 튕김
- 원인: 스테이터스 컴포넌트 등의 타이머와 델리게이트 바인딩을 해제하지 않아, 플레이어가 삭제된 뒤에도 타이머가 삭제된 객체의 함수를 호출
- 해결: 처음에는 스테이터스 컴포넌트의 EndPlay에서 타이머를 정리했고, 같은 문제가 다른 곳에서도 나타나자 모든 C++ 클래스의 EndPlay, UnPossess 등에서 타이머와 바인딩을 해제하도록 전체 정리

#### 멀티플레이 입장 시 초기화 순서 때문에 튕기던 문제

- 원인: 폰, 플레이어 스테이트, HUD가 준비되는 타이밍이 서로 맞지 않음. 예를 들어 클라이언트의 플레이어 스테이트가 준비되기 전에 서버가 채팅 메시지를 멀티캐스트하거나, 로컬에만 있는 HUD를 다른 머신에서 갱신하려 함
- 해결: 엔진의 기본 스폰 흐름(PostLogin → HandleStartingNewPlayer → RestartPlayer → GetDefaultPawnClassForController → SpawnDefaultPawnFor)을 오버라이드해 역할별 캐릭터를 순서대로 생성하고, HUD 갱신은 IsLocallyControlled로, 플레이어 스테이트 접근은 유효성 검사로 감쌈

#### 데이터 오타 하나로 튕기던 문제

- 원인: 데이터 테이블의 재료 아이템 코드 오타
- 해결: 오타를 고치고, 잘못된 데이터가 들어와도 튕기지 않도록 널 체크 방어 코드 추가

### 저장 시스템

#### 불러온 상자 인벤토리가 쓰레기 값이 되던 문제

- 원인: 포인터 변수를 직렬화하면 값이 아니라 메모리 주소가 저장돼, 게임을 다시 켜고 불러오면 쓰레기 값이 들어옴
- 해결: 포인터 대신 인벤토리 컴포넌트 자체를 직렬화하도록 변경. 구조체 내부 변수에도 SaveGame 지정이 따로 필요하다는 점까지 정리

#### 불러온 뒤 HUD 연결이 끊기던 문제

- 원인: 플레이어를 불러올 때 SaveGame 옵션 없이 역직렬화해 포인터 값이 덮어쓰여짐
- 해결: SaveGame 변수만 복원하도록 역직렬화 방식을 수정

#### 나무를 베면 떨어지는 아이템들의 저장 ID가 중복되던 문제

- 원인: 드롭 아이템을 스폰할 때 GUID까지 복제됨
- 해결: 스폰 후 GUID를 새로 발급

### 멀티플레이

#### 패키징 빌드에서 클라이언트가 로비에 들어가지 못하던 문제

- 원인: 스팀 넷 드라이버 설정이 없어 NetDriver 생성 실패
- 해결: SteamSockets를 켜고 엔진 설정(DefaultEngine.ini)에 SteamNetDriver를 지정

#### 기절하면 클라이언트 이동이 끊기던 문제

- 원인: 기절 상태의 이동 속도가 서버에서만 바뀌어 서버와 클라이언트 속도가 다름
- 해결: 기절 변수의 OnRep 함수에서 양쪽 이동 속도를 같이 바꾸도록 수정

#### 버린 아이템의 꾹 눌러 상호작용 시간이 0이 되던 문제

- 원인: 아이템을 드롭하며 설정한 값을 부모 클래스의 BeginPlay가 나중에 실행되면서 기본값 0으로 덮어씀
- 해결: 상호작용 시간을 데이터 테이블에서 가져오도록 바꾸고 BeginPlay의 덮어쓰기 코드를 제거

### 기타

#### 물에 빠르게 들어가면 산소 게이지가 사라지던 문제

- 원인: 수영 모드가 수면 → 수중으로 빠르게 바뀔 때 수면 모드의 산소 회복이 멈추지 않음. 회복이 끝까지 진행되면서 "산소 가득 참" 이벤트가 발생해 게이지가 숨겨짐
- 해결: 모드가 바뀔 때 이전 모드의 회복 처리를 확실히 중단하도록 수정

#### 얕은 물 위를 걸어다니던 문제

- 원인: 물 마시기 상호작용을 위해 물의 Visibility 채널을 Block으로 설정했는데, 발 IK 계산 트레이스가 여기에 걸림
- 해결: 상호작용 전용 트레이스 채널을 새로 만들어 분리

#### 재접속하면 월드 원점(0, 0, 0)에서 다시 태어나던 문제

- 원인: 에디터 테스트용 닉네임을 붙이는 코드가 스팀 닉네임을 덮어써, 저장된 플레이어 데이터를 찾지 못함
- 해결: 테스트 코드가 실제 스팀 닉네임을 덮어쓰지 않도록 수정
